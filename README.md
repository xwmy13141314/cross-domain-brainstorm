# 跨域迁移脑暴

一个用于 **产品创新 / 功能创新 / 交互创新 / 服务模式创新** 的 Claude Skill。

它不靠行业内横向借鉴，而是通过 **跨域机制迁移** 打破思维惯性：

- 锁定问题
- 抽取跨域领域
- 提炼底层机制
- 强制嫁接
- 发散出创意池
- 收敛成 Top 3

这个 Skill 的目标不是直接给“标准答案”，而是先帮用户跳出同质化方案，炸出一批真正有变化感的候选创意。

## 它解决什么问题

很多产品 brainstorm 之所以低效，不是因为团队不努力，而是因为大家的思路都被困在同一个行业框架里。

最后会发生几件事：

- 点子越想越像同行
- 方案越聊越保守
- 一开会就在讨论可行性
- 还没发散，就已经开始否定

`跨域迁移脑暴` 的作用，就是强行打破这种局面。

它通过“抽领域 → 抽机制 → 强制嫁接”的方式，让团队从别的行业、别的系统、别的产品逻辑里借到 **底层解法**，而不是抄表面功能。

## 适合什么场景

适合在这些情况下使用：

- brainstorm / 头脑风暴卡住
- 现有方案过于同质化
- 想从其他行业借机制，而不是抄功能
- 团队共创时需要快速打开思路
- 产品、功能、交互、服务模式都需要重新找突破口

高匹配表达包括：

- “帮我跨界脑暴一下这个功能”
- “帮我用别的行业机制想新方案”
- “当前脑暴卡住了，帮我炸点新想法”
- “想做一些不那么像同行的产品创意”

## 不适合什么场景

这个 Skill **不适合** 用来做：

- 行业研究 / 竞品研究
- 根因分析 / 复盘
- 战略判断 / 方向选择
- PRD 定稿
- 文章写作

如果你的目标是“研究清楚”，那应该先用别的 Skill；
如果你的目标是“先炸出新点子”，这个 Skill 才是对的。

## 核心原则

- 迁移 **底层机制**，不要照搬 **表面功能**
- 发散阶段不提前否定
- 收敛阶段再引入理性判断
- 先追求候选数量和多样性，再追求最优解
- 如果结果只是“把别人的界面 / 按钮 / 玩法搬过来”，判定为低质量创意

这也是它和普通 brainstorm 的区别：

它不是泛发散，而是 **结构化跨域发散**。

## 默认工作流

1. 锁定目标对象和单一核心痛点
2. 抽取 3 个异质领域
3. 提炼每个领域的底层机制
4. 将机制强制嫁接到目标对象上
5. 发散出创意池
6. 快速收敛出 Top 3 和验证建议

## 文件说明

### `SKILL.md`
技能主体，定义：
- 触发条件
- 适用边界
- 最小工作流
- 默认输出格式
- 失败兜底策略

### `references/domain-library.md`
跨域领域库，提供：
- 传统行业领域
- AI / 数字领域
- 服务 / 流程领域
- 抽样建议与反差组合建议

### `references/mechanism-examples.md`
机制提炼方法，重点解决：
- 什么叫“机制”

- 高质量迁移 vs 低质量迁移
- 常见机制类型清单

### `references/output-templates.md`
标准输出模板，包含：
- 创意池模式
- Top 3 模式
- 单人模式
- 团队主持模式

### `references/example-session.md`
完整演练案例，用来校准这个 Skill 的输出风格和深度。

## 典型使用方式

这个 Skill 最适合搭配真实问题使用。

例如：

- AI 笔记 App，用户记完不回看
- 智能手表，户外运动时操作复杂
- 企业知识库，内容太多但不知道哪个能直接用
- 订阅产品，用户注册后留存不足

如果它跑得好，你会发现它生成的点子不是“像同行”，而是“像借了别的领域的脑子”。

## 建议搭配的其他 Skill

- `hv-analysis`
  - 用于深度研究、竞品分析、行业分析
- `product-thinking`
  - 用于产品方向判断、机会分析
- `khazix-writer`
  - 用于把创意写成文章或长文

## 安装后建议

优先用两个真实案例试跑：

1. AI 产品
   - 例如：AI 笔记 App、AI 写作工具、AI Agent 工具
2. 非 AI 场景
   - 例如：智能手表、家电、线下服务流程

这样最容易验证这个 Skill 是否真的在“迁机制”，而不是在“抄功能”。
