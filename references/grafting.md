# 结构嫁接与发散 v0.2

这份文档用于 `跨域迁移脑暴` 的 Step 4。

目标不是“把 A 行业的功能搬到 B 产品”，而是：

> 把来源领域的**要素、关系、反馈结构**映射到目标领域，保留因果骨架，替换载体和上下文。

## 一、先做结构映射，不要先想点子

### 映射表

| 来源要素 | 目标要素 | 保持的关系 | 断裂的假设 | 谁验证反馈 | 适配改造 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

填表规则：

- **来源要素**：机制里的角色/节点/规则，不是 UI。
- **目标要素**：目标领域里对应的角色/节点/规则。
- **保持的关系**：哪些因果关系必须保留？例如“小步投入 → 即时反馈 → 累积”。
- **断裂的假设**：目标领域不满足来源领域的哪个条件？例如“笔记没有生命体征”。
- **谁验证反馈**：外部可验证、自我报告、还是无人验证？
- **适配改造**：为了保住关系，需要替换/新增什么？

如果“保持的关系”写不出来，说明你还没有机制，只有比喻。

## 二、五个表面复制测试

每个候选在进入收敛前，跑这五个测试：

1. **去名测试**：去掉来源领域名字，这个创意还能作为因果机制成立吗？
2. **替换测试**：把来源机制换成一个通用最佳实践，创意还剩下什么？
3. **行为测试**：它是在改变用户行为/系统结构，还是只改了一个界面/按钮/文案？
4. **依赖测试**：它是否必须依赖来源领域的特定世界观/内容才成立？
5. **验证测试**：反馈信号由谁验证？只有自我报告时，标“装饰风险”。

**判定**：

- 5 问全过：可进入收敛。
- 3-4 问过：标“待改造”，补验证/补条件。
- ≤2 问过：标“表面迁移”，不得进入组合。

## 三、强制变体菜单

发散阶段至少用 3 种，避免 10 个点子都是同一个方向换皮。

| 变体 | 问题 | 例子 |
|---|---|---|
| 简化版 | 去掉一半能力，只保留核心回路，会怎样？ | 不做等级，只做“一次回顾 + 一个可用产出” |
| 反向版 | 把机制反过来用，会怎样？ | 不奖励“记得多”，奖励“复用得多” |
| 10x 版 | 把某个变量放大 10 倍，会怎样？ | 10 倍反馈频率；10 倍内容量；10 倍用户数 |
| 1/10 版 | 把成本/复杂度压到 1/10，会怎样？ | 只做一张卡片，不做系统 |
| 去掉约束版 | 假设最大约束不存在，会怎样？ | 假设没有隐私限制、没有预算限制 |
| 换利益相关者版 | 用户/买家/运营者/监管者互换，会怎样？ | 从“给用户看”变成“给主管看” |
| 换节奏版 | 实时 ↔ 批量 ↔ 长周期，会怎样？ | 从每日提醒变成季度复盘 |
| A×B 组合 | A 的必要条件 × B 的反馈信号，会怎样？ | 分诊的风险分级 × 审计的对账 |
| 负向迁移 | 把来源机制的反模式迁过来，会怎样？ | 过度追踪 → 刻意不显示进度 |

## 四、A×B 组合矩阵

单个领域 × 单个机制，只能得到线性类比。真正的新颖性常来自组合。

做法：

1. 选两个机制 A、B（来自不同领域）。
2. 取 A 的**必要条件/约束**，B 的**反馈信号/验证方式**。
3. 组合成一个新回路。
4. 问：这个组合解决了单个机制解决不了的什么问题？

### 示例

- A = 急诊分诊的“按未来损失风险分配注意力”
- B = 审计的“每笔主张都有对应项 + 对账”
- 组合 = “风险票据”：每条高价值笔记带一个“未来损失风险”评分，并记录它被哪些决策/文档使用；当风险高且长期未被使用时，浮出来要求对账。

这个组合比“做个每日回顾”更具体，也比“做个风险评分”更有验证结构。

## 五、负向迁移

不是所有迁移都要“学优点”。把来源机制的反模式迁过来，往往能产生更好的设计。

步骤：

1. 写出来源机制的**失效形态**。
2. 问：如果目标产品刻意避免这个失效，会长成什么样？
3. 生成“反向设计”。

### 示例

- 来源：快递的“全程追踪” → 失效形态：过度追踪造成焦虑、隐私侵犯。
- 负向迁移：笔记产品**刻意不显示**“你还有 37 条未读”，只在关键决策点提示 1 条最值得看的。
- 来源：游戏的“连续签到” → 失效形态：断签焦虑、为签到而签到。
- 负向迁移：允许“补签”或“无惩罚跳过”，把激励从“连续”改成“累计有效使用”。

负向迁移不是“反着玩”，而是**把失败模式当成设计约束**。

## 六、嫁接的三个层次

| 层次 | 迁移什么 | 质量 | 例子 |
|---|---|---|---|
| 表面 | 外观、按钮、玩法名称 | 低 | 给笔记加经验条 |
| 结构 | 要素、关系、反馈回路 | 中-高 | 小任务 → 即时反馈 → 累积 → 解锁 |
| 系统 | 结构 + 制度/验证/激励 | 高 | 结构 + 外部验证 + 责任/补偿 |

多数“跨域创意”停在表面；好创意至少到结构；高风险场景要到系统。

## 七、工作示例：急诊分诊 → AI 笔记

### 映射表

| 来源要素 | 目标要素 | 保持的关系 | 断裂的假设 | 谁验证反馈 | 适配改造 |
|---|---|---|---|---|---|
| 患者到达 | 新笔记/新问题 | 进入待处理池 | 笔记没有生命体征 | 用户行为（弱） | 用“未解决问题/截止日期/依赖”做风险信号 |
| 风险分级 | 未来复用价值评分 | 按未来损失分配注意力 | 笔记价值难以即时判断 | 用户/同事（中） | 用可解释信号，不用黑箱分数 |
| 优先级标签 | 今日 3 条重点 | 有限注意力只给高价值 | 用户可能不信任标签 | 用户可改（中） | 允许一键“降级/升级” |
| 定时复评 | 决策点复评 | 条件变化时重排 | 笔记没有固定复评周期 | 事件触发（中） | 会议前/打开相关文档时触发 |
| 资源重排 | 动态推荐 | 注意力随风险变化 | 推荐可能打扰 | 用户反馈（弱） | 默认安静，只在关键点提示 |

### 生成的创意（示例）

1. **风险票据**：每条决策笔记带“未来损失风险 + 复评日期 + 来源/使用记录”。
2. **决策点复评**：不按日提醒，而在会议前、打开相关文档时，浮出 1 条“最该看”的笔记。
3. **异常笔记报告**：每周只列“高价值但 30 天未被使用”的笔记，附一个“为什么它可能重要”的解释。
4. **一键降级**：用户可以把推荐标记为“不重要”，系统学习，不反复打扰。
5. **交接卡**：团队笔记在负责人变更时，生成结构化交接卡，要求接手人读回确认。

### 表面复制测试

- 去掉“急诊”后，仍能说清“按未来损失分配注意力 + 决策点复评” → 过。
- 换成“每日回顾”这个通用最佳实践，创意还剩“风险信号 + 验证记录” → 过。
- 改变的是注意力分配和验证结构，不只是加一个进度条 → 过。
- 不依赖医院/生命体征 → 过（已替换为笔记信号）。
- 反馈由用户行为/同事确认，部分是自我报告 → 标“中等装饰风险”，需要真实复用指标。

## 八、嫁接失败模式

| 失败 | 表现 | 修法 |
|---|---|---|
| 只映射标签 | “游戏化”“平台化”“社交化” | 回到要素/关系 |
| 映射了要素，丢了关系 | 有任务、有等级，但没有“反馈→累积” | 补关系 |
| 忽略验证结构 | 源领域靠外部验证，目标只有自评 | 补验证者，或标装饰风险 |
| 忽略激励 | 源领域奖励质量，目标奖励数量 | 检查谁受益/谁承担成本 |
| 忽略容量 | 源领域有团队/基础设施，目标没有 | 做 1/10 版 |
| 比喻膨胀 | 听起来美，无法对应 | 逐项填映射表 |
