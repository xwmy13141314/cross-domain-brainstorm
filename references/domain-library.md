# 跨域领域库

这份领域库用于 `跨域迁移脑暴` 的 Step 2。

目标不是帮用户“选同行”，而是故意引入 **足够异质** 的外部领域，强制打破行业惯性。

## 使用原则

默认优先抽 3 个领域，尽量满足：

- 1 个传统行业
- 1 个数字 / AI 领域
- 1 个服务 / 流程领域

如果用户自己已经指定了某个领域，再补 2 个反差更大的领域。

避免：
- 抽到和目标对象过于同类的领域
- 抽到只有“表面功能差异”但底层机制相同的领域
- 一次抽太多领域，导致注意力分散

## 领域选择建议

### 适合优先抽的领域类型

- 强反馈领域
- 强流程控制领域
- 强风险预警领域
- 强个性化生成领域
- 强激励体系领域
- 强追踪与状态可视化领域

### 不建议优先抽的领域类型

- 和目标对象极度同类的领域
- 用户自己已经反复提到过的熟悉领域
- 只能提供“界面参考”，很难提炼机制的领域

## 传统行业领域

| 领域 | 典型底层机制 | 常解决的问题 |
|------|--------------|--------------|
| 游戏 | 升级反馈、任务驱动、成就激励 | 用户持续参与、正向反馈不足 |
| 汽车 | 主动预警、一键模式、自适应调节 | 操作风险高、信息复杂、环境变化快 |
| 快递 | 全流程追踪、状态节点更新、异常拦截 | 用户不确定、过程不可见、结果焦虑 |
| 超市 | 关联推荐、组合销售、会员分层 | 选择困难、客单价提升、复购不足 |
| 酒店 | 标准化服务、分级体验、场景打包 | 服务不一致、体验缺乏层次 |
| 银行 | 风险校验、权限分层、流程留痕 | 高风险操作、信任成本高 |
| 机场 | 分段引导、节点提示、容量调度 | 路径复杂、等待焦虑、资源拥堵 |
| 教育 | 分层学习、阶段目标、即时反馈 | 学习动力弱、进度不透明 |
| 健身 | 打卡坚持、计划编排、阶段目标 | 长期坚持困难、目标模糊 |
| 军事 | 协同响应、任务分工、异常优先级 | 多角色协同、复杂环境决策 |
| 医院挂号 | 排队分流、优先级分诊、流程预约 | 资源稀缺、等待低效 |
| 咖啡机 / 家电 | 一键场景、预设模式、低认知负担 | 操作复杂、学习成本高 |

## AI / 数字领域

| 领域 | 典型底层机制 | 常解决的问题 |
|------|--------------|--------------|
| AI 绘画 | 权重控制、负面约束、迭代重绘 | 输出不稳定、结果不精准 |
| AI Agent | 自动执行、多步骤协同、反馈迭代 | 流程繁琐、重复操作多 |
| 推荐系统 | 用户标签、行为学习、动态排序 | 信息过载、匹配效率低 |
| 搜索引擎 | 检索排序、意图匹配、结果分层 | 找不到、筛选难、优先级混乱 |
| 短视频平台 | 低门槛触发、高频反馈、沉浸流 | 冷启动难、参与度低 |
| prompt 工程 | 输入约束、结构模板、结果控制 | 结果发散、表达不稳定 |
| 大模型微调 | 小样本校正、风格对齐、任务适配 | 通用模型不贴业务 |
| 多模态交互 | 多输入融合、上下文补足、模态切换 | 单通道信息不够、理解断裂 |
| 知识库系统 | 结构化沉淀、引用追踪、上下文复用 | 知识积累但不可复用 |
| 自动化工作流 | 条件触发、串并联任务、失败回滚 | 人工串流程太重 |

## 服务 / 流程领域

| 领域 | 典型底层机制 | 常解决的问题 |
|------|--------------|--------------|
| 外卖 | 实时追踪、超时补偿、阶段状态感知 | 过程焦虑、等待不确定 |
| 会员体系 | 分层权益、成长激励、身份认同 | 留存不足、复购弱 |
| 客服系统 | 分流、工单优先级、标准回复 | 问题堆积、响应低效 |
| 订阅制 | 周期提醒、持续价值交付、流失预警 | 一次性交易难沉淀长期关系 |
| 景区票务 | 限流预约、时段分配、入口核验 | 高峰拥堵、资源失衡 |
| 健身课程 | 周期计划、签到约束、陪伴式监督 | 用户中途流失 |
| 社群运营 | 共同目标、身份激励、轻任务参与 | 活跃不足、参与断层 |
| 人才招聘 | 多轮筛选、标签匹配、流程漏斗 | 筛选低效、误配率高 |
| 咨询服务 | 诊断→方案→陪跑→复盘 | 用户只获得建议，无法落地 |
| 售后服务 | 问题追踪、状态更新、补偿闭环 | 问题反复、信任流失 |

## 快速抽样建议

### 默认抽样法

当用户没有指定领域时，按这个顺序抽：

1. 从传统行业抽 1 个
2. 从 AI / 数字领域抽 1 个
3. 从服务 / 流程领域抽 1 个

### 强反差抽样法

当用户脑暴严重卡住时，优先选反差更大的领域，例如：

- 目标是 AI 产品 → 抽医院挂号 / 军事 / 超市
- 目标是硬件产品 → 抽 AI Agent / 会员体系 / 搜索引擎
- 目标是服务流程 → 抽游戏 / 汽车 / AI 绘画

### 避免同类抽样

以下情况尽量避免：

- 做 AI 笔记产品，却抽“其他笔记软件”
- 做外卖产品，却抽“团购平台”
- 做智能手表，却抽“其他穿戴设备”

如果抽到同类领域，优先重抽。

---

## 给 Claude 的提醒

抽领域的目标不是“找参考答案”，而是“制造结构性偏差”。

好的跨域领域应该让人第一反应是：
- “这也能迁过来？”
- “这个领域和我们居然能连上？”
- “原来可以借这个机制，不一定借这个功能”
