# 机制提炼与检验 v0.2

这份文档用于 `跨域迁移脑暴` 的 Step 3。

目标不是“分析这个领域有哪些功能”，而是提炼：

> 它到底靠什么**因果结构**，在什么条件下，解决了什么问题；条件不成立时，它会退化成什么？

## 一、什么叫“机制”

机制不是功能，不是 UI，不是行业术语，也不是一个漂亮的比喻。

机制是一个**可复述的因果安排**：

> 当 [触发条件] 出现，[主体] 按 [规则/约束] 行动，得到 [反馈信号]，从而 [结果]；
>
> 它在 [必要条件] 下成立；若 [失效前提]，它会退化成 [退化形态]。

### 最小三元组

任何机制卡，至少写得出这三件事：

1. **触发条件**：什么情况下启动？
2. **反馈信号**：谁在什么信号上判断“有效/没效”？
3. **失效前提**：若什么不成立，它会退化成什么？

写不出第三项，大概率是功能，不是机制。

### 机制 vs 功能

| | 功能 | 机制 |
|---|---|---|
| 形态 | 一个按钮、页面、模块、玩法 | 一个因果回路/规则/反馈结构 |
| 例子 | 经验条、进度条、提示词框 | 小任务 → 即时反馈 → 累积 → 解锁 |
| 能否迁移 | 只能换皮 | 可以换载体、换场景、换对象 |
| 失效条件 | 通常不写 | 必须写 |
| 验证 | 看有没有这个功能 | 看反馈由谁验证、条件是否成立 |

## 二、机制卡（9 个字段）

| 字段 | 写什么 | 反例 |
|---|---|---|
| 名称 | 动词/因果短语，不用功能名词 | “成长系统” ❌；“小任务→即时反馈→累积→解锁” ✅ |
| 触发条件 | 什么情况下启动 | 只写“有成长体系” ❌ |
| 反馈信号 | 谁在什么信号上判断有效/没效 | 只写“有反馈” ❌ |
| 因果链 | 触发 → 行为 → 反馈 → 结果 | 只写“有成长体系” ❌ |
| 必要条件 | 机制成立需要什么 | 漏掉“反馈必须可信” ❌ |
| 失效前提 | 若＿不成立，退化为＿ | 只写“有风险” ❌ |
| 可迁移内核 / 不可迁移上下文 | 一句话内核；哪些是源领域特有 | 含“游戏化”；把世界观也搬走 ❌ |
| 证据/置信度 | 例子/来源 + H/M/L | 无来源、全高置信 ❌ |
| 目标映射 | 来源要素 → 目标要素 | 只写“会变成什么” ❌ |

## 三、五个机制测试

1. **去名测试**：去掉来源领域名，还能说清因果链吗？
2. **移除测试**：如果移除这个机制，源领域的结果会明显变差吗？
3. **条件测试**：目标领域满足它的必要条件吗？不满足时，能改造吗？
4. **名词测试**：它是不是只是一个功能名词/UI 形态/行业黑话？
5. **验证测试**：反馈信号由谁验证？如果只有自我报告、没有外部验证者，标“装饰风险”。

五问里有两问答不上来，这张卡就不该进入嫁接。

## 四、六个机制样例

### 样例 1：游戏 — 成长回路

- **名称**：小任务 → 即时反馈 → 累积 → 解锁
- **触发条件**：用户完成一个可感知的小任务
- **反馈信号**：经验值/等级/解锁动画；系统判定，玩家可见
- **因果链**：任务 → 完成 → 即时反馈 → 成长累积 → 更高难度任务 → 持续参与
- **必要条件**：任务颗粒度可调；反馈即时且可信；成长可累积/可展示；难度与能力匹配
- **失效前提**：如果反馈与真实价值脱节、任务可被刷量、成长数值膨胀，就退化为“空洞积分”
- **可迁移内核**：把长期价值拆成可完成的小闭环，让每次投入都有可见、可累积的进步
- **不可迁移上下文**：游戏世界观、虚拟身份、娱乐性奖励
- **证据/置信度**：游戏设计领域高；迁到生产力场景的证据为低
- **目标映射**：任务 → 笔记；反馈 → 回顾；累积 → 知识资产；解锁 → 新场景

**注意**：这张卡不等于“给产品加经验条”。经验条只是它的一个 UI 实现；如果没有“任务可完成、反馈可信、成长可累积”，它就是装饰。

### 样例 2：快递 — 可验证节点 + 异常处理

- **名称**：可验证里程碑 + 异常路径 + 补偿
- **触发条件**：一个长流程开始，用户与执行者分离
- **反馈信号**：扫描节点、签收、延误赔付；外部可验证
- **因果链**：寄出 → 节点扫描 → 状态可见 → 异常拦截 → 赔付/重派 → 签收
- **必要条件**：节点可物理验证；责任可追溯；异常有处理路径；用户能看到状态
- **失效前提**：如果节点是自报的、没有责任主体、异常没有补偿，状态流就退化为“装饰性进度条”
- **可迁移内核**：把长流程拆成可验证的里程碑，给异常一条明确的处理路径
- **不可迁移上下文**：物流网络、扫描设备、赔付规则
- **证据/置信度**：物流行业高；迁到知识/服务流程为中等
- **目标映射**：包裹 → 任务/笔记；扫描 → 可验证的使用/确认；异常 → 卡点/遗忘；赔付 → 补救

### 样例 3：医院急诊分诊 — 风险分级 + 动态复评

- **名称**：按未来损失风险分配注意力，并在决策点复评
- **触发条件**：需求超过容量，信息不完整
- **反馈信号**：生命体征、复评结果、外部结果；由医护/设备验证
- **因果链**：到达 → 快速风险分级 → 优先级标签 → 资源分配 → 定时/触发复评 → 重排
- **必要条件**：存在可观察的风险信号；有复评机制；有重排权限；外部验证
- **失效前提**：如果风险信号不可观察、没有复评、没有重排权限，分诊就退化为“先来后到”
- **可迁移内核**：按“未来价值损失的风险”而非“到达顺序”分配注意力；在决策点复评
- **不可迁移上下文**：生命体征、临床责任、急诊队列
- **证据/置信度**：医疗领域高；迁到知识工作为中等
- **目标映射**：患者 → 笔记/任务；风险信号 → 未解决问题/截止日期/依赖；复评 → 决策点；重排 → 今日重点

### 样例 4：剧场排练 — 低成本试演 + 结构化反馈

- **名称**：围读 → 走位 → 试演 → 反馈 → 修订
- **触发条件**：最终演出成本高，不能直接上台
- **反馈信号**：导演/同伴/观众反应；主观但可结构化
- **因果链**：文本 → 围读 → 动作/走位 → 试演 → 反馈 → 修订 → 再试演
- **必要条件**：安全的试错空间；可观察的反馈；修订时间；明确的演出目标
- **失效前提**：如果没有低成本的试演、没有具体反馈、没有修订，排练就退化为“反复对词”
- **可迁移内核**：在低成本环境里预演真实使用，用结构化反馈驱动修订
- **不可迁移上下文**：舞台、剧本、观众
- **证据/置信度**：戏剧领域高；迁到产品/服务为中等
- **目标映射**：剧本 → 方案；排练 → 原型/试演；导演 → 评审；观众 → 用户

### 样例 5：复式记账 / 审计 — 双向记录 + 对账

- **名称**：每笔主张都有对应项，并定期对账
- **触发条件**：一方记录、另一方可能不信任
- **反馈信号**：借贷平衡、对账差异、审计抽样；外部可验证
- **因果链**：交易 → 双向分录 → 期末对账 → 差异/异常 → 调整/追责
- **必要条件**：双向结构；独立对账；可追溯凭证；异常处理
- **失效前提**：如果分录是自报的、没有独立对账、没有凭证，账本就退化为“流水账”
- **可迁移内核**：每个主张都要有来源、对应项和独立核对；异常要浮出来
- **不可迁移上下文**：会计科目、货币、审计准则
- **证据/置信度**：财务/审计领域高；迁到知识/服务为中等
- **目标映射**：交易 → 决策/主张；分录 → 来源/使用记录；对账 → 定期核对；异常 → 未使用/矛盾/过期

### 样例 6：免疫系统 — 识别 + 记忆 + 二次应答

- **名称**：识别模式 → 保留记忆 → 二次快速应答
- **触发条件**：再次遇到已识别模式
- **反馈信号**：分子识别、免疫反应、病原清除；外部可验证
- **因果链**：首次暴露 → 识别 → 记忆细胞 → 再次暴露 → 快速应答 → 更新记忆
- **必要条件**：模式识别；记忆维持；匹配质量反馈；可更新
- **失效前提**：如果只靠表面相似、没有记忆维持、没有误报校正，就会交叉反应或遗忘
- **可迁移内核**：维护一个小型“记忆集”，在相关情境出现时快速识别并重放，同时用反馈校正误报
- **不可迁移上下文**：分子生物学、免疫耐受
- **证据/置信度**：生物领域高；迁到知识工具为低-中（wildcard）
- **目标映射**：病原 → 相关问题/情境；记忆细胞 → 高价值笔记；二次应答 → 快速重放；误报 → 不相关推荐

## 五、低质量 vs 高质量：用测试说话

### 例 1：游戏 → 笔记

**低质量**：给笔记加经验条/等级图标。

- 去名测试：去掉“游戏”，剩下“加经验条”，没有因果链 → 失败。
- 移除测试：移除经验条，笔记回看行为几乎不变 → 失败。
- 条件测试：笔记没有“任务完成”的清晰边界 → 失败。
- 验证测试：经验值由系统自评，没有外部验证 → 装饰风险。

**高质量**：把“小任务 → 即时反馈 → 累积 → 解锁”迁移成“可完成的回顾任务 → 可用的知识资产 → 主题地图 → 新场景解锁”。

- 去名测试：仍能说清“小步投入 → 可见产出 → 累积 → 新能力”。
- 移除测试：移除这个回路，回看行为会退回到“想起来才看”。
- 条件测试：任务可拆、产出可用、累积可见；满足。
- 验证测试：产出被实际使用（引用/复用）才算反馈；有外部信号。

### 例 2：快递 → 学习产品

**低质量**：给课程加一个物流进度条。

- 去名测试：只剩“进度条”，没有节点验证/异常处理 → 失败。
- 验证测试：进度由系统自报，没有“学会”的外部信号 → 装饰风险。

**高质量**：把“可验证里程碑 + 异常路径”迁移成“可验证的掌握节点 + 卡点异常 + 补救路径”。

- 去名测试：仍能说清“里程碑可验证、异常有处理”。
- 条件测试：掌握节点可通过练习/项目验证；满足。
- 验证测试：练习结果/项目产出由外部标准验证。

### 例 3：AI 绘画 → 写作

**低质量**：加一个“提示词框”和“风格按钮”。

- 去名测试：只剩 UI，没有“权重/负向约束/迭代修正”的因果结构 → 失败。
- 条件测试：写作任务是否有可分解的权重？需要改造。

**高质量**：把“权重控制 + 负向约束 + 迭代修正”迁移成“重点标记 + 排除项 + 逐轮重写”。

- 去名测试：仍能说清“可控输入 → 受约束输出 → 反馈修正”。
- 验证测试：用户是否真的逐轮修正、输出是否更接近意图；可用 A/B 测试。

## 六、机制丰富度（H/M/L）

| 等级 | 标准 | 用法 |
|---|---|---|
| H | 有清晰触发、反馈、失效前提；有外部验证；有可迁移的因果内核 | 优先选 |
| M | 有机制但反馈/验证较弱，或上下文依赖强 | 可用，需改造 |
| L | 主要是氛围、美学、行业术语；说不清失效前提 | 换掉，或只做 wildcard 且标低置信 |

## 七、常见失败模式

| 失败 | 表现 | 修法 |
|---|---|---|
| 功能名词冒充机制 | “成长系统”“推荐算法”“游戏化” | 写因果链 + 失效前提 |
| 缺验证者 | 反馈由系统/自己说了算 | 找外部信号，或标“装饰风险” |
| 上下文错配 | 源领域靠法律/责任/基础设施，目标没有 | 补条件，或换机制 |
| 激励错配 | 源领域奖励 A，目标奖励 B | 检查谁受益、谁承担成本 |
| 容量错配 | 源领域有大量人力/数据，目标没有 | 做 1/10 版，或换更轻的机制 |
| 比喻膨胀 | 听起来很美，但无法对应要素 | 回到映射表，逐项对应 |
