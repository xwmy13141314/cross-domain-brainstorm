# Release Notes v0.4.0 — 双模式：灵感（品类碰撞）+ 决策（机制迁移）

**日期**：2026-11-20  
**类型**：行为更新（minor）  
**一句话**：把技能拆成两种模式——**灵感模式**（品类碰撞房 → 挑号 → 筛选房，先创意后可行性）与**决策模式**（v0.3 全套机制迁移流程原样保留）。

---

## 1. 为什么要改

v0.3 发布后用一道真实产品题（阔直板三防机）连测三轮，暴露了结构性问题：

| 轮次 | 做法 | 结果 |
|---|---|---|
| R1 | 抽到制度/流程牌（保险精算/冷链/剧场） | 产出保险/订阅类创意，用户否：「这都是保险机制类，跟产品创新没什么关联」 |
| R2 | 换物理机制牌（电力网/伤口愈合/蚁群） | 产出"合理但无聊"的卡扣公差类创意，用户否：「还不如最开始的版本，就是要找不同跨品类强行结合，先看创意，再看是否能实现」 |
| R3 | 直接拿品类强行结合（魔方/犰狳/渔轮/战术手电…32 组） | 用户开始挑号：18 手电尾按、20 边框水平仪可行，「继续发散」 |

结论：**发散阶段混进审查器、品类距离不够大、收敛纪律挤压灵感**——这不是参数问题，是缺一种模式。调研 GitHub 同类仓库（danium/lateral-thinking 的 random-stimulus 规则与弃牌文化、disney-creative-ideation 的 Dreamer/Critic/Realist 三室分房与"brief 不含硬约束"）后确认了设计方向。

## 2. 新增：灵感模式（创意题默认）

流程：**Stage A 碰撞房 → Gate 挑号 → Stage B 筛选房**。

- `references/collision-room.md`：碰撞房规则。brief 只有题面/人群/软偏好，**绝不写预算/资源/历史**；每组四行=品类[世界·具象]→属性→嫁接→爽点；**禁词**=成本/BOM/可行性/风险/认证；弃牌公开+冗余测试（不用刺激物也想得出的弃）；11 招扩容器；批失败诊断；元模式收尾必做。
- `references/stimulus-library.md` + `assets/stimulus-deck.json`：**品类刺激库 100 张牌 / 11 个世界**（工具间/玩具箱/军品战场/生物解剖/厨房/运动/农具渔猎/航海航空/医疗急救/文具乐器/抽象制度），Quick 12-15 组、Deep 40-60 组；≥5 世界、同世界不相邻、≥2 具体+1 抽象、气质相近世界减半抽。
- Gate 挑号：**只报编号，不评估不推荐**；挑 0 个→报元模式，问"更远还是更近"；继续发散→把存活/否决信号回灌过滤器再出 10-15 组（编号累计）。
- `references/triage-room.md`：筛选房只审挑中的。有用性三问（谁真用/干什么活/比现有多好）；可行性阶梯 L0 纯软件 → L1 边框嵌件 → L2 运动机构（必给 1/10 降级版）→ L3 原理能做；show-stopper=安全/认证/伦理/BOM>整机 10%；Top-3 出七行落地卡。

## 3. 保留：决策模式（v0.3 全套）

带预算/否决者/要落地的题仍走 v0.3 六步：题型判定 → 三个数 → 距离采样 → 机制卡 → 嫁接 → 组合+红队。**Step 0 先判模式**（灵感信号=「创意几组/新方向/炸想法」；决策信号=带预算要落地；判不准默认灵感），两库不混抽；灵感 Top-3 立项时转决策模式补红队。

## 4. 其他修改

- `SKILL.md`：版本 0.4.0；Step 0 双模式分叉；三种速度（灵感 Quick 25-35 分钟/灵感 Deep 60-90/决策 Quick 20-25/决策 Deep 60-90）；失败兜底新增两条真实教训（全是服务模式类→换物理世界牌；合理但无聊→审查器混进发散房）。
- `references/output-templates.md`：新增模板〇=灵感模式（Stage A 交付/ Gate 后交付/灵感写作规则）。
- `scripts/domain_sampler.py`：双 deck 双模式；`--stimulus --stim-count --near-world --ban-world`；同世界不相邻、≥5 世界、抽象保底；self-test 覆盖 66 领域+100 刺激牌。
- `scripts/validate_skill.py`：VERSION 0.4.0；100 牌 schema 校验；v0.4 anchor 检查；evals ≥8 case。
- `evals/`：Case 8（阔直板三防机灵感题，陷阱全部来自真实失败）；G13 门槛（灵感模式专用，决策标 NA）；灵感模式 4 数换算（碰撞组数/可用率/存活率/类型回潮）；A/B 协议 v0.3 vs v0.4，灵感题 35 分钟预算。

## 5. 升级步骤

1. 覆盖安装整个 skill 目录（新增 `references/collision-room.md`、`references/triage-room.md`、`references/stimulus-library.md`、`assets/stimulus-deck.json`）。
2. 跑 `python scripts/validate_skill.py` 应输出 `VALIDATION OK`。
3. 跑 `python scripts/domain_sampler.py --self-test` 应输出 `SELF-TEST OK`。
4. 若你之前的流程依赖"所有题都走六步机制迁移"，改为先判模式：创意题默认灵感模式。
5. 决策模式行为与 v0.3.0 完全一致，无需迁移。

## 6. 兼容性

- 决策模式：v0.3 全部行为保留（机制卡/落地卡/两门/三查/红队 8 问）。
- `domain-library.md` 内容不变（66 牌），仅元数据版本号升 0.4.0。
- `example-session.md` / `example-session-hardware.md` 仍标注为 v0.2 机制演示，未重写。
- 旧输出模板仍在；灵感模式模板是新增（模板〇），不替换决策模板。

## 7. 已知限制

- 品类刺激库 100 张为手工策展，尚未经大量真实题检验；可用率基线（≥15%）是假设值。
- Gate 挑号依赖用户参与；单轮自动跑（无人挑号）会退化为"筛选房自评"。
- 灵感模式尚未接入先例检索；Top-3 的先例三查沿用 v0.3 规则（未查可标）。
- Quick 25-35 分钟比 v0.3 的 20-25 分钟更长；用"挑号不打分"换时间，是否划算待 A/B 验证。
