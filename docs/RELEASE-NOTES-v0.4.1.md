# Release Notes v0.4.1

> 补丁版：修 v0.4.0 验收发现的一个入口漏洞，补一个灵感模式示例。无流程变更。

## 为什么发

v0.4.0 双模式上线后跑了三个验收：

| 验收 | 结果 |
|---|---|
| 决策模式回归 · 居家养老运营题（Case 7） | ✅ 23/25（v0.2.1 同题 14/25，五个已知失败全修复） |
| 决策模式 · AI 笔记题（Case 1） | ✅ 21/25，11 项全过，机制浓度持平偏强 |
| 灵感模式 · 三防机真实题（Case 8） | ✅ 12 组碰撞+3 弃牌，类型回潮禁令真实生效 |

唯一结构性发现（来自 AI 笔记题验收）：**模式门入口漏洞**——"产品团队 + 具体行为/留存问题 + 要可推进方向"的题，字面上没有预算/否决者字眼，按 v0.4.0"判不准默认灵感"会被路由进碰撞房。这是经典决策题，不是灵感题。

## 修改内容

### 1. 模式门补边界判据（SKILL.md）

三条同时满足即判**决策模式**，即使字面像灵感题：

1. 团队执行者在问（产品/运营/店主）；
2. 问题具体到行为/留存层（"记完就不看了"，不是"帮我创意几组"）；
3. 输出要能推进（不是纯要灵感）。

反向澄清：只有**个人探索、无指标、纯要灵感**才默认灵感模式。决策信号表新增样例原话。

### 2. 新增灵感模式完整示例（references/example-session-inspiration.md）

基于 2026-11-20 三防机真实会话剪裁：碰撞房四行 → 弃牌死因（3 张，全部死于撞已否类型）→ 元模式 → Gate 只报编号 → 两种真实用户反应（"再多发散 10 组" / 挑号+否决+继续发散）→ 否决信号回灌过滤器 → 筛选房三问 + L 阶梯 + 2 张七行落地卡 → 立项转决策模式交接。用户引语全部真实。

### 3. README 补 Windows GBK 提示

GBK 控制台会把 sampler CLI 的中文输出打成乱码：`PYTHONIOENCODING=utf-8` 或模块直调写 UTF-8 文件（示例命令已给）。

### 4. 其他

- evals/cases.md Case 1 加模式边界注记（AI 笔记题应判决策模式）；
- validator 升 0.4.1：新增 v0.4.1 anchor 检查（边界判据/示例文件/GBK 提示）；
- 两个 deck JSON 仅版本元数据 0.4.0→0.4.1，内容零变更。
