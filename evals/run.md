# A/B 评测协议 v0.4

用于比较 `cross-domain-brainstorm` v0.3 与 v0.4，或比较不同模型/提示。

目标不是证明“新版本更好”，而是回答：

> 在同样的问题和时间预算下，v0.4 是否产出更深、更可追溯、更可测试、更安全、**更可落地**的创意？灵感模式下，是否产出**品类距离更大、可用率更高**的产品创意？

## 一、准备

- 版本：v0.3（基线，v0.3.0 tag）与 v0.4（候选，当前仓库）。
- Case：`evals/cases.md` 的 8 个（Case 7 为运营/执行题、Case 8 为灵感题，两者必须包含）；先跑 3 个（含 Case 8），有信号再扩到 8 个。
- 评委：3 人（产品/设计/工程各一），至少 1 人不懂这个 skill 的内部结构。
- 工具：计时器、盲标（A/B 随机）、评分表（`evals/rubric.md`）、录音/截图。
- 模型：同一个模型、同一个温度/参数；如果模型支持系统提示，保持系统提示一致。
- 会话：每个 case × 版本用独立会话；不要让模型看到另一个版本的输出。

## 二、盲标与顺序

1. 把 v0.2 和 v0.3 随机标为 A/B（每个 case 可以不同）。
2. 随机决定先跑 A 还是 B。
3. 评委不知道哪个是 v0.2；只知道 A/B。
4. 每个评委独立打分，不讨论；合议时再看版本。

## 三、运行步骤

### 1. 安装/加载 skill

- v0.3：使用 v0.3.0 tag 的 `SKILL.md` + references。
- v0.4：使用当前仓库。
- 确保模型能读到 `SKILL.md` 和按需读取 references（含 `stimulus-library.md` / `collision-room.md` / `triage-room.md`）。
- 不要在 prompt 里额外提示“用机制卡/用红队/用落地卡/用碰撞房”；让 skill 自己驱动。

### 2. 同一个 prompt

对每个 case，使用同一句用户请求。例如：

> “我们做 AI 笔记 App，用户记完不回看。帮我做一次跨域脑暴，给我几个值得推进的方向。”

Case 8（灵感题）示例：

> “帮我创意几组，准备做一个阔直板三防机。”

不要给任何一方额外信息。

### 3. 时间预算

- 决策模式：Quick，**25 分钟上限**（v0.3 基线同预算）；记录自然完成时间。
- 灵感模式（Case 8）：**35 分钟上限**（含 Gate 等用户挑号的时间，不含用户思考）。
- 如果超时，截断并标记“超时”；超时本身是负面信号。
- Deep 模式单独比较，不混入 Quick 结果。

### 4. 记录输出

- 保存完整输出（Markdown/截图）。
- 记录：开始/结束时间、是否超时、是否读取 references、是否追问、是否卡住。
- 不要编辑输出；评委看原始版本。

### 5. 评分

- 每个评委先独立填 `rubric.md`。
- 先过 13 个门槛（含 G11 成本/容量门、G12 先例三查、G13 灵感模式）；任何 Fail 标记“不合格”（G13 对决策模式输出标 NA）。
- 再打 7 维分（灵感模式输出改记 4 个数，见 rubric.md）。
- 合议：只讨论分歧 ≥1 分的维度；记录原因。
- 最后揭盲 A/B。

## 四、样本量与轮次

| 阶段 | Case 数 | 目的 |
|---|---|---|
| Pilot | 3（含 Case 8 灵感题） | 校准 rubric、发现明显问题 |
| Main | 8 | 主比较 |
| Deep dive | 1-2 | 对失败/争议 case 做质性复盘 |

每个 case × 版本至少 1 次；如果模型输出波动大，重复 2 次，取平均或记录方差。

## 五、判定规则

### v0.4 胜出

- 决策模式：至少 4/7 维平均分不低于 v0.3；机制深度、可追溯、可测试、伦理不倒退；**G11/G12 通过，且 Case 7 落地卡可执行**（v0.4 未动决策主链，视为不倒退即可）。
- 灵感模式（Case 8）：**碰撞组 ≥12 且可用率 ≥15%**（用户挑中 / 总组数）；品类距离 ≥5 世界；零禁词；弃牌有死因；Gate 只报编号；用户否过的类型不回潮。
- 有用性/可读性不下降；
- 门槛通过率不低于 v0.3；
- 完成时间在预算内（决策 25 分钟、灵感 35 分钟）。

### 平手/不划算

- 灵感模式碰撞组多但可用率 <10%（数量换不来质量）；
- 只高 1-2 维，但时间明显更长；
- 机制更深但用户读不懂/不愿用；
- 灵感模式被决策模式污染：发散段出现成本/可行性词汇；
- 落地卡有了但全是“未知”，没有推动缩范围。

### v0.4 失败

- 灵感模式碰撞组 <12，或品类距离退化（大量制度/流程牌出现在创意题里）；
- 决策模式任何维度倒退；
- 门槛通过率更低；
- 先例三查出现编造（直接判负）；
- 评委更愿意用 v0.3。

失败时，不要直接改 rubric；先看是哪个环节失败（碰撞/挑号/筛选/距离/机制/嫁接/收敛/红队），再改 skill。

## 六、质性复盘

每个 case 记录：

- 最好的一个创意，为什么好？
- 最差的一个创意，为什么差？
- 有没有“表面迁移”漏过测试？
- 有没有“机制卡写不出失效前提”？
- 有没有“评分偏向保守”？
- 有没有“伦理风险被忽略”？
- 有没有“成本/容量被跳过或假精确”？
- 有没有“先例编造”？
- 用户是否知道下一步做什么？执行者明早能不能照做？
- （灵感题）发散段有没有混进审查器词汇？Gate 有没有忍住不推荐？用户否过的类型有没有回潮？

## 八、偏差控制

| 偏差 | 控制 |
|---|---|
| 版本泄漏 | 盲标；评委不看文件名/开头 |
| 顺序效应 | 随机先 A/B；每个 case 重新随机 |
| 评委漂移 | 先校准一个样例；中途不换锚点 |
| 时长不公 | 同预算上限（决策 25 分钟/灵感 35 分钟）；记录自然时间 |
| 提示泄漏 | 同一句 prompt；不额外提示任何版本的方法 |
| 选择偏差 | 8 个 case 覆盖数字/物理/高风险/公共服务/灵感题 |
| 光环效应 | 先过门槛，再打分；不先看总分 |
| 沉没成本 | 预先写判定规则；不因为“做了很久”而放行 |

## 九、给评委的说明

> 你看到的是一份跨域脑暴输出。请先检查它是否说清了“借了什么机制、怎么映射、谁来验证”，再打分。  
> 不要因为“看起来专业/很长”给高分；不要因为“想法奇怪”给低分。  
> 先过门槛，再看七维。  
> 如果你不确定，写备注，不要猜。
