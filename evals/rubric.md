# 评测 Rubric v0.2

用于给 `cross-domain-brainstorm` 的输出打分，或比较 v0.1 / v0.2。

**先过门槛，再打分。** 门槛失败时，分数再高也不合格。

## 一、门槛检查（Pass / Fail）

| # | 门槛 | 判定 |
|---|---|---|
| G1 | 每个创意都能追到一个机制卡和一个框定的问题 | 是/否 |
| G2 | 每张机制卡写得出“失效前提” | 是/否 |
| G3 | 每个 Top 创意通过“去掉来源名”测试 | 是/否 |
| G4 | 每个 Top 创意回答“反馈信号由谁验证” | 是/否 |
| G5 | 反平庸测试：Top 创意不能被现有产品一句话覆盖 | 是/否 |
| G6 | 组合里有 safe / bold / wildcard | 是/否 |
| G7 | 每个 bet 有假设、最危险假设、便宜实验、阈值、kill 条件、证伪成本 | 是/否 |
| G8 | 红队完成：伦理、现状、验证者、二阶效应 | 是/否 |
| G9 | 没有依赖操纵/成瘾/隐私侵犯/歧视/不可逆伤害的创意被放行 | 是/否 |
| G10 | Quick ≤2 页 / Deep ≤4 页；不确定判断标 H/M/L | 是/否 |

**任何一项 Fail → 该输出不合格，先修，不进入评分比较。**

## 二、七维评分（0-2）

### 1. 机制深度

| 分 | 锚点 |
|---|---|
| 0 | 功能名词/UI/行业黑话，没有因果链 |
| 1 | 有因果链，但缺反馈信号或失效前提 |
| 2 | 触发 + 反馈 + 因果链 + 必要条件 + 失效前提，且经得起“移除测试” |

### 2. 距离与桥

| 分 | 锚点 |
|---|---|
| 0 | 同行借鉴/直接竞品；或只是行业标签不同 |
| 1 | 有距离，但桥牵强；或没有结构轴差异 |
| 2 | ≥3 轴差异（含至少 1 个结构轴）+ 清晰的结构桥 + 说明为什么不是同类 |

### 3. 新颖性

| 分 | 锚点 |
|---|---|
| 0 | 现有产品常见；换说法 |
| 1 | 有变化，但可预期；或只是组合已知功能 |
| 2 | 非显然；能说清“和现有方案的本质差异”；不是靠怪 |

### 4. 有用性

| 分 | 锚点 |
|---|---|
| 0 | 不解决框定问题；或违反硬约束 |
| 1 | 部分解决；或只解决次要问题 |
| 2 | 直接作用于框定的用户/结果；有清晰的行为改变 |

### 5. 可追溯

| 分 | 锚点 |
|---|---|
| 0 | 说不清来源/机制/映射 |
| 1 | 能说来源，但映射弱；或验证者不清 |
| 2 | 来源 → 目标逐项对应；保留关系/断裂假设/验证者都写清 |

### 6. 可测试

| 分 | 锚点 |
|---|---|
| 0 | 无法验证；或只有“做用户访谈” |
| 1 | 有方向，但没有可证伪假设/阈值 |
| 2 | 假设 + 最危险假设 + 便宜实验 + 阈值 + kill 条件 + 证伪成本 |

### 7. 伦理

| 分 | 锚点 |
|---|---|
| 0 | 有害/操纵/成瘾/歧视/隐私侵犯，且未处理 |
| 1 | 有风险，但未识别/未缓解 |
| 2 | 风险已识别/缓解；有自主权/可逆性/验证者 |

### 合格线

- 总分 ≥10/14；
- 机制深度、可测试、伦理不得为 0；
- 所有门槛 Pass。

### 比较规则（A/B）

- 逐维比较，不只看总分。
- v0.2 胜出：至少 4/7 维更高，且有用性/可读性不下降。
- 如果 v0.2 更慢但只高 1 维，视为不划算；回到 Quick 路径减负。
- 记录“完成时间”和“评委是否愿意再用”。

## 四、评委校准

1. 先一起评一个样例（可用 `references/example-session.md` 的节选），对齐锚点。
2. 每个评委独立打分，不讨论。
3. 合议时只讨论分歧 ≥1 分的维度。
4. 记录分歧原因（对“机制”的理解不同/对“有用”的定义不同）。
5. 如果两个评委对同一维度差距 ≥2 分，引入第三评委或重新校准。

## 五、常见误判

| 误判 | 表现 | 纠正 |
|---|---|---|
| 把“复杂”当“深” | 术语多、结构长 | 看失效前提和验证者 |
| 把“怪”当“新” | 不常见但没用 | 看问题匹配/可测试 |
| 把“可行”当“好” | 只选渐进式 | 可行性是门槛，不是优点 |
| 把“用户喜欢”当“伦理” | 忽略操纵/成瘾 | 单独看伦理维度 |
| 把“有引用”当“可追溯” | 只列来源，没有映射 | 看来源→目标逐项对应 |
| 把“有实验”当“可测试” | 实验不能证伪 | 看阈值/kill 条件 |
